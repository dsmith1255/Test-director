# Delivery status and target acceptance

Version **0.4.1** is a source-tested release candidate that adds compact recording and safe AI end behavior to the collection-first 0.4.0 workflow. It has **not yet been installed or recorded live**. The workflow records sequential X/Y/Z tire stints with requested labels, observed compound and conditions, AI/human controller readback, pit handoff, and continuous raw telemetry. Collection has **no clock or lap quota**. The guided C/R/F/E/M/V program remains optional: **Spa → Silverstone GP → Imola → modern Monza GP**, with 20–22 planned program laps per track. Its 315-minute schedule is advisory, and accepted laps and explicit confirmations determine advancement. Local Content Manager **0.8.2895.40668** installed the earlier 0.4.0 Lua-only ZIP with the expected app and two modes, and launched FH26 at Spa/default. All three installed manifests read 0.4.0. The CSP runtime log confirms **0.2.11 b3465**; an earlier 0.2.7 reading from file metadata was incorrect. The corrected `[WINDOW_...]` manifest registered one window. The separate portable companion GUI opened and detected the local AC root. Tyler's installation remains unverified.

On October 22, the 0.4.0 FH26/Spa collection smoke test saved run `20261022015027-42569870`. Its raw results bundle is retained locally outside the GitHub source tree. The manifest records `selection="collection"`, car `rss_formula_hybrid_2026`, track/layout `spa/default`, mode `wimna-ai-thermal`, and extended physics observed true. The AI request was followed by native `isAIControlled` ON readback at 0.025 simulation seconds; all **5,042 samples** in the labeled stint were AI controlled. Ending the 0.4.0 run requested AI OFF and native readback confirmed OFF. The export contains 15 events and one capability record, with **19.86 Hz** effective sampling, zero sequence gaps and zero reported drops. It observed C4 tires, 36 °C ambient air and 29 °C track surface, plus per-wheel native core temperature, wear and pressure. The requested X/Y/Z label, compound and setup label were left blank in this smoke test. There was one pit outlap and one timed lap; **both were native invalid with one cut each**, so neither is comparable pace evidence. No human stint or tire swap was tested. After recording ended, the unattended car was seen stopped against a barrier in the UI. That observation occurred **outside the saved raw run**; there is no crash sample or contact event in it.

The run also confirms the collection path can retain a measured simulator trace for modeling, but not that the complete model is calibrated. Direct requested/delivered/recovery electrical power and `battery_energy_j` remained unavailable; the installed SDK offers no verified direct RSS channel for them. The native KERS fields retain their unverified meaning and are not silently treated as battery energy. Custom thermal results remain **analysis only**, with no native component temperature or verified live restriction. The installed 0.4.0 recorder used roughly 93 MB over about 287 seconds of elapsed test time, which is too large to extrapolate casually to many long stints.

The **0.4.1** storage change writes compact JSONL chunks with a per-chunk channel dictionary and completed-chunk footer, accepts old and new chunks in the companion, compresses SQLite sample payloads, and exports expanded raw records as reproducible gzip JSONL. The storage path passed **108 tests**. Reimporting the saved 0.4.0 live Spa run offline retained 5,042 samples and 15 events; `collection_stints.json`, `collection_laps.csv`, `collection_samples.csv` and `run_summaries.json` were identical. That reimport produced a 30,867,456-byte SQLite file versus 186,855,424 bytes with the prior storage path, and about 4.73 MiB of gzip raw telemetry export. These are offline results from legacy live data. The 0.4.1 in-game writer, its effective storage rate, frame impact and recovery behavior still need a live check before longer collection runs.

The **0.4.1** AI end change separates data collection from control release. **End Collection Run** records the end and leaves AI control as observed; it does not send AI OFF. **Stop AI Driver at Rest** is available only when native speed readback is at or below 2 km/h, then waits for native AI-OFF readback. Pit and handoff markers also leave control unchanged. The 0.4.0 barrier observation motivated this source-tested behavior, but it has **not yet been verified in game**. Ending recording does not brake or park the car; if AI remains ON, keep it driving until safely stopped or exit through the game menu.

The collection app starts both manual and AI runs with `manifest.selection="collection"`. Each stint has a unique ID, requested X/Y/Z label and compound, optional driver-entered setup/profile label, and independent native tire/environment observations. Pit, tire-change and physical-session events preserve the sequence; a compound change or reset closes the active stint. AI and human samples enter one measured simulator-data inventory with controller as a covariate. The analysis exports per-stint summaries, descriptive tire contrasts, human pace anchors and conditional AI-to-human tire scenarios. Matching manually entered setup labels does not prove a matching setup; hashes remain unavailable. Any AI-to-human transfer is an unvalidated assumption until a held-out human check. Source parse, focused Lua control/stint tests and Python collection tests have passed. AI control, the shared session-mode readback and recorder rate were verified locally for one 0.4.0 AI stint; 0.4.1 safe AI end, mixed AI/human handoff, second tire stint, restart recovery and frame impact remain **unverified live**.

The car's physics data are in `data.acd`, so the readable-curve path remains unavailable.
