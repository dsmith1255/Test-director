# Assetto Corsa integration and live verification

## What is packaged

`ac_app/` is an Assetto Corsa root overlay. Its `apps/lua/WimnaTestDirector/` folder is a CSP Lua in-game app. The package contains four Practice-derived modes: `wimna-test`, `wimna-ai-thermal`, `wimna-ai-baseline`, and `wimna-ai-plan-c`. The paired baseline and Plan C modes request automatic AI collection after guarded mode, physics and storage checks. The baseline adds no WIMNA force; Plan C requests a bounded external aero-force proxy and records its parameter identity. Cooling remains analysis-only. The app does not edit RSS car files, setups, track files or CSP configuration and contains no car or track assets. AI and human intervals stay in one simulator-telemetry inventory with controller identity recorded per sample. Match session mode and extended-physics readback before interpreting contrasts. The AI request still needs observed native takeover. The portable Windows companion is delivered separately because the tested Content Manager installation omitted a bundled EXE.

## Build and install

From PowerShell in the source tree, run the complete release build:

```powershell
./Build-Release.ps1
```

This builds `dist/WIMNA-Test-Director-CM.zip` with `apps/` and `extension/` at archive root, plus a separate `dist/WIMNA-Test-Director-companion.zip` containing `wimna-director.exe` and its `_internal` runtime folder. `ac_app/Build-AppPackage.ps1` alone repackages the in-game app and four modes. Drag the CM ZIP into Content Manager and inspect its installation preview. Check that it proposes only the WIMNA app and the four named WIMNA modes under the selected Assetto Corsa root. Extract the companion archive to a user-writable folder and double-click its EXE before driving; keep `_internal` beside it. If Content Manager refuses a custom mode or puts it in a different location, use the same ZIP's `apps/lua/WimnaTestDirector` folder as a manual overlay into the detected AC root, then select normal Practice for driver-run recording. Automatic AI takeover requires a live permitted mode. Use the current root discovered by Content Manager; do not use Tyler's reported path on another machine.

For generated CM presets, allow the custom-mode list to finish loading before starting a session, then check the resulting session for `[RACE] __CM_CUSTOM_MODE` matching the requested variant. Earlier direct launches while CM was stale or loading fell back to ordinary Practice or Quick Race. The short queue pilot also exposed Content Manager's “Settings not specified” error when the Go URI omitted `presetFile`; the corrected launcher includes the exact preset in both stages. A preset file or launch command alone is not proof that the chosen physics mode ran. The runner verified mode, car, track/layout, AI, recorder, completed save and process exit for Spa → Spa, Spa → Monza and Imola → Silverstone GP transitions under supervision. The eight-session overnight queue remains unarmed until an explicit start and current preflight.

The default package does not install a sibling EXE in the Lua app folder. Start the separate companion before driving. The Lua app retains a conditional launch path if a sibling `wimna-director.exe` is manually placed there, using CSP's documented `os.runConsoleProcess()` API. A launch request is not proof the process started; the overlay requires a matching `run_id` response. The companion must be singleton-safe, persist campaign state in Documents and create `director_state.json` for the current run.

After installation, enable the Lua app in Content Manager if the target build requires activation. Select the car, exact track/layout, tire and physical weather setting. Select **WIMNA AI Thermal** for an automatic AI request or **WIMNA Test**/Practice for manual recording. Both custom modes request the app window when loaded; with ordinary Practice, open WIMNA Test Director from the app bar. Enter an X/Y/Z tire test label, requested compound, condition label and optional setup/profile label. Press **Start Collection** or **Start AI Data Collection**. Both create `manifest.selection="collection"`. Labels are manually entered; the observed native compound, air and track temperature, session mode and extended-physics status are saved separately. The setup/profile hashes remain null unless independently obtained.

Record a stint and mark the pit/control handoff; the marker does not change control. In the 0.4.1 candidate, stop the car and have a person ready before pressing **Stop AI Driver at Rest**. That action is unavailable when native speed readback exceeds 2 km/h or is unavailable; verify native AI-OFF readback before taking over. The app does not brake or park the car. Box, change tires, press **End Stint / Box**, edit the labels and press **Start Next Stint**. **End Collection Run** closes recording without requesting AI OFF; if AI remains ON, let it drive until safely stopped or exit through the game menu. Each stint has a unique `collection_stint_id`; raw recording continues through pit travel and tire changes while the run is active. A compound change or native session reset during a stint closes that stint and requires a new start. Collection has no elapsed-time gate or lap quota. **Pause Collection** marks data while simulator motion and recording continue. The older **Start Full Program**, **Resume** and **Individual Test** buttons remain for the C/R/F/E/M/V scheduler. A new app run ID does not imply physical tire or fuel continuity; native session changes retain separate `physical_session_id` suffixes. See [AI Thermal Check](AI_THERMAL_CHECK.md) for the earlier diagnostic and thermal evidence limits.

For uninstallation, remove only `apps/lua/WimnaTestDirector` and the four WIMNA folders under `extension/lua/new-modes/`: `wimna-test`, `wimna-ai-thermal`, `wimna-ai-baseline`, and `wimna-ai-plan-c`. Results in `Documents/WIMNA Test Director` remain for review unless Tyler elects to remove them. No user setup or RSS file is modified by this app.

## Bridge contract

The app writes under the active user's `Documents/WIMNA Test Director/bridge` using `ac.getFolder(ac.FolderID.Documents)`. A storage probe writes and reads `storage_probe.json` before a run is called recordable. `current_state.json` is refreshed about every two seconds. The companion writes `director_state.json` with at least:

```json
{"schema":1,"run_id":"20261020T200000Z-00001234","campaign_id":"...","track":"spa","block_id":"SP R","instruction":"...","lap_progress":"2/5 accepted; 2 attempted","target":"...","recording_status":"...","next_action":"...","state":"record_block"}
```

The app ignores a director state whose `run_id` does not match the active app run. Until a matching state appears, the overlay shows a static run card and explicitly says the director is offline. The static card does not accept laps, advance blocks, or validate settings. `layout_id` comes from `ac.getTrackLayout()` where available, with a folder-path fallback; `default` means no separate layout.

Per-run data are in `bridge/runs/<run_id>/manifest.json` and consecutive `000001.jsonl`, `000002.jsonl`, ... chunks. A full record from installed 0.4.0 or expanded by the 0.4.1 companion has this shape:

```json
{"schema":1,"run_id":"...","physical_session_id":"...-s0","seq":1,"sim_time_s":0.05,"wall_time_utc":"2026-10-20T20:00:00Z","kind":"sample","data":{"speed_kmh":{"value":180.2,"unit":"km/h","source":"CSP_STATE","quality":"available"}}}
```

The 0.4.1 compact recorder format starts a chunk containing samples with a `WIMNA_COMPACT_JSONL_V1` channel dictionary, writes sample value arrays and sparse quality overrides, then closes it with a counted footer. Units and sources are stored in that chunk's dictionary; a changed channel descriptor falls back to an ordinary full JSON record. The companion validates the footer before importing any record and expands every sample into the full record shape shown above. It still reads earlier ordinary JSONL chunks and text-based SQLite rows. New SQLite JSON payloads are compressed; portable result bundles write expanded raw telemetry as `telemetry-*.jsonl.gz` (standard gzip JSON Lines), with uncompressed events and a SHA-256 manifest. The readable CSV is a convenience view and does not replace raw quality or provenance. An offline reimport of the saved 0.4.0 Spa run retained its 5,042 samples and 15 events with identical collection stint, lap, sample and run-summary outputs; the compact writer itself has not yet been live recorded.

Unavailable channel values are JSON `null` with `quality:"unavailable"`; they are never zero-filled. Button and lap events use `kind:"event"` and `data.type`. The in-game choices emit `ui_start_full`, `ui_resume`, `ui_individual`, `ui_pause`, `ui_end`, `ui_issue`, `ui_confirm`, `ui_confirm_learning`, `ui_confirm_profile`, and `ui_skip`. Skip requires a typed reason; skipping validation also requires a separate unavoidable confirmation. Profile confirmation includes explicit `mode:"FRZ_AUTO"` or `mode:"MANUAL_APPLIED"`; the latter requires a driver-entered profile name. Both are driver attestations, not automatic RSS readback. A `lap_complete` event includes native lap index and, when supplied, `previousLapTimeMs` and `isLastLapValid`; current lap timer is not misused as the completed time. A lap-count jump emits `lap_counter_jump` instead of fabricated lap completions. A native session change or car reset at a lap boundary emits `lap_boundary_ambiguous` instead of accepting that lap. Samples continue during **Pause Test** and carry `experiment_paused=true`. `ui_pause` affects the experiment only; it need not pause AC.

Collection starts emit `ui_start_collection` and `collection_stint_start`; the latter records `collection_id`, unique `collection_stint_id`, requested X/Y/Z tire label, requested compound, condition label, optional `setup_label_requested`, observed compound and environment, controller readback, and the stint's physical-session ID. The optional setup/profile label has source `DRIVER_ENTERED_UNVERIFIED`; `setup_hash` and `profile_hash` remain null. Every collection sample has `collection_stint_id`, `is_ai_controlled` and `is_user_controlled` channels. `collection_pit_transition`, `collection_handoff_requested`, `collection_compound_changed` and `collection_stint_end` preserve the pit and tire-change sequence. A compound change or physical reset closes the active stint and requires a new start. The mode scripts try to stamp `wimna-test` or `wimna-ai-thermal` in CSP session-shared storage; the app reads it into manifest `session_mode`, alongside observed `extended_physics` and CSP version. An unavailable stamp remains null. Both AI and human collection traces remain in the measured simulator-data inventory, while collection laps do not advance the separate C/R/F/E/M/V campaign.

`seq` is unique within a run, including deliberately dropped samples. The companion should deduplicate `(run_id, seq)` and report missing sequence numbers and corrupt final chunks. The app keeps a bounded 120-line memory buffer, reserves 20 places for events, targets 20 samples per **simulation** second, and writes roughly one-second chunks. It never backfills missed graphics frames. CSP car state is read from the app update loop, so actual effective channel rates and frame-time cost require live measurement; `current_state.json` reports the aggregate effective sample rate. `sim_time_s` is elapsed in-app simulation time from `ac.getGameDeltaT()` when available; the fallback is pause-gated frame `dt` and is named in `current_state.json`. Wall-clock UTC is separate. The storage probe creates directories explicitly; `io.save(..., true)` requests an atomic write and does not create missing parent directories.

The inspected SDK defines `fuel` in liters, steering in degrees, tire temperatures in Celsius, and wheel load in newtons. `battery_soc_native` and KERS inputs remain unverified generic car-state semantics, not RSS battery energy or signed electrical power. Direct requested, delivered and recovery electrical power and `battery_energy_j` were unavailable in the local 0.4.0 run. Tire wear is labeled `native_fraction_not_life`; it must not be reinterpreted as remaining tire life. `tyreVirtualKM` is not ordinary driven kilometers. Tire pressure, wheel slip, and brake disc temperature retain unverified native units. `engineLifeLeft` is recorded as native life state, never as engine temperature. Track surface and ambient air are separate channels. More fields have source-level SDK definitions but need live value and rate checks on the target build.
