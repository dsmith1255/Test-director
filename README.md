# WIMNA Test Director

**0.5.0 experimental candidate:** Two opt-in AI modes pair an unchanged baseline with a small Plan C aerodynamic prototype. The prototype requests bounded extra downforce and drag through CSP's Physics API; it does not edit or redistribute the installed FH26 car. Every run records its variant and assumed parameters. The custom cooling model remains analysis-only. This version needs an in-game paired smoke test before its physical effect or overnight behavior can be claimed. See [the prototype run plan](docs/PLAN_C_PROTOTYPE.md).

**Collection workflow:** **Start Recording** and **Start AI Recording** lead directly to unrestricted data collection. They count raw lap crossings without settings or acceptance gates; every crossing retains its validity and context. The optional C/R/F/E/M/V protocol is separately labeled as guided. See [Tyler's guide](docs/TYLER_GUIDE.md).

**For Tyler:** Follow [installation and driving instructions](docs/TYLER_GUIDE.md). For the GitHub handoff and release assets, use the [shipping checklist](docs/GITHUB_RELEASE.md).

Offline Assetto Corsa data collection and modeling software for the WIMNA 2026 case. AI and human driving both provide simulator telemetry, with controller identity saved per sample. The 0.5.0 companion adds an exploratory baseline versus Plan C prototype analysis with exact variant hashes and observed-condition checks; a matched AI difference is not a measured human upgrade gain. The existing replayable four-track C/R/F/E/M/V campaign remains available as a guided protocol. `Build-Release.ps1` creates separate Content Manager and portable companion archives on Windows.

## Driver setup

1. Build or obtain `dist/WIMNA-Test-Director-CM.zip`. Drag it into Content Manager and inspect the installation preview. It should place only `apps/lua/WimnaTestDirector/` and the two `extension/lua/new-modes/` folders `wimna-test/` and `wimna-ai-thermal/` in the detected AC root. Confirm the exact FH26 car and Spa/default layout for the first track. Resolve and lock Silverstone GP, Imola and modern Monza GP before their blocks; historic Monza and banking layouts are excluded.
2. Extract `dist/WIMNA-Test-Director-companion.zip` to a writable folder, keeping `wimna-director.exe` and `_internal/` together. Double-click `wimna-director.exe` before driving. The companion is a GUI and needs no terminal or Python installation on Tyler's computer. Do not launch the executable from inside the ZIP.
3. In the companion, use the folder picker if AC is not detected. Import the **Update6** workbook before case screening. Set car and track IDs, fuel, SOC and map/profile details only where the installed car and a pilot support them. Missing values remain unavailable rather than zero.
4. For tire data, choose one track/layout and a physical weather setting in Content Manager. Use **WIMNA AI Thermal** when requesting automatic AI control; use **WIMNA Test** or Practice for manual collection. Open the app, optionally enter a tire test label such as X, the requested compound, a condition label such as hot, and a setup/profile label. Press **Start Recording** or **Start AI Recording**. These labels are driver-entered requests; the recorder saves the observed tire compound, air/track temperatures and physics mode independently.
5. Run a stint and mark the pit/control handoff. Bring the car to a stop and have a driver ready before pressing **Stop AI Driver at Rest**; the action is unavailable above 2 km/h or without speed readback. Confirm native AI-OFF readback, box and change tires. Press **End Stint / Box**, update the label and requested compound to Y, then **Start Next Stint**. Repeat for Z or another condition. **End Collection Run** closes recording but leaves AI control unchanged; if AI remains ON, keep it driving until safely stopped or exit through the game menu. Pit travel and tire changes stay in raw telemetry; complete comparable laps are identified later. There is no clock or lap quota in collection mode. Pause Collection marks the experiment but does not pause Assetto Corsa or stop telemetry.
6. Export the results folder from the companion. `collection_stints.json`, `collection_samples.csv`, `collection_laps.csv` and `collection_channels.json` accompany the raw telemetry and report. Installed 0.4.0 exports JSONL; 0.4.1 and later export equivalent expanded records as gzip JSONL. Keep `Documents/WIMNA Test Director` as the data master. The optional C/R/F/E/M/V program uses **Start Guided Protocol**, **Resume Guided Protocol** or **Individual Test**.

See the [data collection run card](docs/DATA_COLLECTION.md) and [integration guidance](docs/INTEGRATION.md) for the target smoke test, bridge fields and Content Manager fallback. ## Campaign

Collection mode is open-ended: stop or change tire when the data question is answered, with no clock or lap quota. The optional guided scheduler runs C (three accepted learning laps, usually three to five attempts), R (five), F (two), E (four), M (three) and V (three) in this order: **Spa → Silverstone GP → Imola → modern Monza GP**. It plans 20–22 program laps per track, or 80–88 across all four, plus out-laps and warmup. Accepted laps and confirmations advance those campaign blocks. Its 315-minute template is advisory only. Out-laps and warmup remain in raw telemetry and are excluded from comparable flying-lap summaries.

`campaign.template.json` is the editable seed. Its four track/layout IDs come from the local installed track inventory (`spa/default`, `ks_silverstone/gp`, `imola/default`, `monza/default`); confirm each ID on Tyler's installation before relying on assignment. Null car settings and tolerances are intentional and need target discovery and pilot data. A new physical game start does not restore old tire, fuel or component state.

## Developer workflow

Python 3.10+ and only the standard library are needed for source tests and replay. From the project folder:

```powershell
python -m unittest discover -s tests -v
python -m wimna discover --output discovery.json
python -m wimna replay --output sample_results
python -m wimna import-case C:\path\to\Update6.xlsx --output case_update6.json
python -m wimna inspect-car C:\path\to\assettocorsa\content\cars\rss_formula_hybrid_2026 --output vehicle_data.json
python -m wimna ingest
python -m wimna report --case-import case_update6.json --output results_export
```

The Python command is for development and diagnostics; Tyler uses `wimna-director.exe`. `Build-Release.ps1` checks pinned PyInstaller and Tcl/Tk, runs tests, builds a portable GUI bundle, verifies it after extraction, creates the separate companion and Content Manager ZIPs, and writes SHA-256 release hashes. The build requires Python on the **build** machine only. If the selected Python lacks Tcl/Tk scripts, provide compatible directories with `-TclLibrary` and `-TkLibrary`; `-PythonPath` and `-OfflineSitePackages` select an existing offline build runtime.

## Data and evidence

The CSP app writes short JSONL chunks under `Documents/WIMNA Test Director/bridge/runs/<physical_run_id>`. The companion imports them idempotently into a WAL SQLite store. Each collection stint has a unique ID and requested labels separate from native tire/environment observations. AI and human samples share the same measured-simulator-data inventory; controller is a covariate, not an automatic exclusion. A human competitive lap can anchor a conditional transfer of an observed AI tire contrast, but that transfer is an **ASSUMED** scenario until checked against a held-out human stint. Setup/profile text is manually entered and unverified; a matching label is not a matching setup hash. Exports contain manifests, telemetry, events, collection tables, model parameters, forecasts, validation results, a report and hashes. `SYNTHETIC` fixtures never enter measured totals.

Model outputs retain CASE, MEASURED, PHYSICS_DERIVED, ASSUMED and SYNTHETIC evidence, plus calculation mode and physical-effect status. Thermal nodes are custom modeled state. Assumption profiles are engineering examples, not identified failure limits. Analysis-only derating is not recorded as a power loss Tyler experienced. The case's 60-lap race and Plan C introduction remain editable screening assumptions; case pit deltas are not treated as full pit-lane loss.

Readable `.ini`/`.lut` car data are inventoried and hashed without unpacking `data.acd`. Unknown units and whether a curve is active remain unresolved until verified against the installed car and SDK. Requested controls and observed effects are distinct; the current Lua app guides RSS map/profile changes manually and does not claim a writable RSS or thermal actuator.

## Uninstall and restore

Remove only the WIMNA app and `wimna-test` and `wimna-ai-thermal` mode folders from the AC root used during installation. Remove the extracted companion folder separately. The app does not edit car data, setups, or RSS profiles, so no original game files need restoration. Preserve the Documents results folder for review or delete it separately at Tyler's request.
